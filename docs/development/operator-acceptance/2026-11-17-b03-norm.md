### 来源与适配

原始上游仓库：[ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp)，下列SHA均属于该仓库内的ggml源码，不是另一个独立ggml仓库的SHA。本地参考为只读 `/home/sakura/codespace/llama.cpp`。

| 来源 | 本批抽取范围 |
|---|---|
| `72a9269172290829c503c351e2b68ca2f7af2bc7` / #24582 | CPU NORM/L2_NORM 按输入/输出各自 stride 寻址，保留连续快路；Vulkan NORM 使用已有 unary push constants，两个 shader 按四维 stride 与 descriptor misalignment offset 寻址；Vulkan 仅声明 F32 输入/输出，CUDA/WebGPU 拒绝行内不连续输入；上游20个非连续行测试 |
| `c1a4febe9d107de438922f7c8ebb88108d235ea4` / #31890 | 仅两个 norm shader 的 `row >= ne01*ne02*ne03` 返回，避免向上取整的多维 dispatch 访问尾行；不抽取其他算子或关闭 pipeline robustness 的变更 |

- 不带入原提交的 SQR/SQRT/SIN/COS/CLAMP/LEAKY_RELU unary 重构、shader generator 修改、公共 API 或 Metal GROUP_NORM。`80d2c0c2c56e4a1bbf74be98f64b99927bf230bc` 是 Metal 批次，仍未实施。
- 保留本地128字节 unary host/GLSL ABI，不引入上游120字节 packed-fastdiv 结构；pipeline、host参数与shader同步调整。
- **CPU精度适配**：新 strided NORM 路径用 `ggml_float` 累加 sum/variance，保持已有连续 CPU 路径的累加精度，不机械照搬来源的 float 累加。独立 public-API probe 对宽1025、值1e8的常量输入，连续/转置两种布局均观察 `max_abs=0`；不是 GPU 大偏置数值稳定性验收。
- **CUDA能力适配**：新 padded-inplace oracle 暴露旧 kernel 始终按连续输出布局写回。实测两例错误后，将门控补全为 `ggml_is_contiguous_rows(src0) && ggml_is_contiguous(op)`，仅拒绝未支持的输出，不扩写 CUDA kernel；普通连续输出、padded 输入和既有连续 inplace 仍运行。

### 测试、红绿与结果

沿用 `test-backend-ops`，另加22个独立 oracle 用例：奇数宽7、batch维、padded/非零offset view、列stride、inplace、较大eps，以及511/512/513和262143/262144/262145行。预期从实际输入快照按double标量公式独立生成，分别核对两个backend的有限值和绝对/相对误差，不只比较CPU reference。按节点执行并保留sentinel比较；不声称完整检查了inplace backing的所有空洞。

| 检查 | 实际观察 |
|---|---|
| 修复前 CPU NORM/L2_NORM 非连续行 | 各触发 `nb[0] == sizeof(float)` 断言，退出134 |
| 修复前 Vulkan L2 非零offset oracle | 使用本轮新目录构建的旧runtime库复验，普通/inplace两例均数值错误，退出1；旧零offset view十例仍通过 |
| 修复前 Vulkan 非连续行 | 4个独立oracle被拒绝，0/0不是通过；改后实际执行并通过 |
| 最终 CPU / NVIDIA RTX 5060 Vulkan | 各82/82，退出0，无unsupported；含原40例、上游新增20例、独立oracle22例 |
| 最终 CPU ASan + UBSan | 新Debug构建，82/82，退出0，无sanitizer错误 |
| CUDA门控补齐前 | 加载真实driver后77/79，两例padded inplace错误，退出1；初次devShell加载stub只发现CPU、零CUDA用例，明确不计通过 |
| 最终 NVIDIA RTX 5060 CUDA | 含既有RMS_NORM回归，共77/77，退出0；另26例按能力拒绝（非连续行24、padded inplace2），不计通过 |
| CUDA memcheck | 小型oracle实际运行4/4，另6例按能力拒绝；`ERROR SUMMARY: 0 errors`，退出0 |
| Vulkan GPU-assisted validation | 独立oracle22/22，无Validation Error；插桩日志显示buffer越界相关pass计数为0，故不作为尾行越界动态红绿证明 |

尾行修复依据是上游补丁、实际dispatch几何及源码边界核对：513行会分发1024组，262145行会分发524288组。旧版尾行数值同样通过；robustness可能屏蔽越界，不把普通数值或GPUAV绿灯夸大为动态越界检出。默认robustness保持不变。
