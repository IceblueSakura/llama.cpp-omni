## 组内实测

通过 `test-backend-ops` 复用已有 norm 与融合图 fixture，窄形状 `{4,1,65536,1}` 和 `{4,1,1,65536}` 分开命中 y/z；位置 ID 保持小值以隔离 dispatch 而不放宽容差，SET_ROWS 继续独立使用排列索引。GROUP_NORM 用 `{3,1,1,65537}`、一组每 batch：对运行上限为 65535 的 llvmpipe 命中 x 越界和最后一排的多余 groups。

| 检查 | 实际结果 |
|---|---|
| RTX 5060 CUDA 红灯 | NORM、RMS_NORM、L2_NORM、RMS_NORM_MUL_ADD 各两轴，8/8 旧 kernel `invalid configuration argument`，各退出 134。 |
| RTX 5060 CUDA 绿灯 | 边界 **11/11**；定向回归 **190/190**，另 26 例按已有门控拒绝，不计通过。跨界 memcheck/synccheck 各 **8/8**、0 错误；RMS 的 racecheck **4/4**、0 hazards。 |
| RTX 5060 Vulkan 红灯 | RMS_NORM 及 RMS_NORM_MUL_ROPE 的 y/z 4 例均触发 `maxComputeWorkGroupCount` 断言，退出 134。 |
| RTX 5060 Vulkan 绿灯 | 边界 **11/11**；拆分回归 141/141、5/5、75/75，均退出 0。GDB 核对 y、z 的 RMS+MUL+RoPE（2 个附加 op）和 y 的 VIEW+SET_ROWS（4 个附加 op）均实际走融合入口。 |
| llvmpipe Vulkan GROUP_NORM | 旧实现 `maxComputeWorkGroupCount` 断言，退出 134；最终 **1/1**，退出 0。软件设备证实真实 x 上限，不是 NVIDIA x 超限或 z 分割验收。 |

首次 NVIDIA Vulkan 合跑虽报告 221/221，退出时一次 `double free or corruption (out)`，退出 134，不计为通过。随后拆组与原合跑命令的三次复跑 **221/221** 均退出 0，无 Vulkan validation 错误，未能复现退出异常，原因未确认。原始失败保留。未验 HIP、CUDA Graph capture/replay 或性能；大维度用例不等于任意元素数或所有设备的验收。

## 复验入口

使用当前工作区的 `build-operators-b03-cuda`（sm120，CUDA 12.9.86）与 `build-operators-b03-vulkan`（RelWithDebInfo），RTX 5060 driver 615.78.08。llvmpipe 使用从项目锁定输入构建的 Mesa 26.2.3；主机的 Mesa 26.3.0 要求更高版本 glibc，不能把首次只枚举 CPU 的 `0` 退出码当 Vulkan 证据。未改主机运行时。

```bash
# 从仓库根目录执行，先保留已有 evidence；脚本内列出设备、filter 和 sanitizer 参数。
nix develop --no-update-lock-file .#cuda --command \
  bash build-operators-b11/evidence/group-checks.sh cuda green
nix develop --no-update-lock-file .#vulkan --command \
  bash build-operators-b11/evidence/group-checks.sh vulkan green
```

`build-operators-b11/evidence/group-{cuda,vulkan}-{red,green}/` 保留原始日志、实际用例数、运行库/源码身份校验及辅助 GDB 记录。B11 在当前可验目标上统一交付；整组唯一适用但未移植项是 HIP reflect。后续 PR 提取本组生产代码及测试，不带入本地约定与验收文档。
